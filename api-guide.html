REST-API und Token Guide

Hier steht, wie Nutzer einen GitHub Token erzeugen, warum er nötig sein kann und welche API-Endpunkte GitSuccess verwendet. Endlich Token-Drama mit Struktur.

Warum brauche ich einen Token?

GitSuccess kann öffentliche Repositories grundsätzlich ohne Token analysieren. GitHub begrenzt unauthentifizierte API-Anfragen jedoch stark. Mit Token erhältst du ein höheres Rate-Limit und weniger Blockierungen bei mehreren Analysen.

Wichtig: Den Token niemals in den Code schreiben, nicht committen und nicht öffentlich teilen. Er gehört nur lokal in das Eingabefeld der App.

Token erstellen

1
GitHub öffnen und oben rechts auf das Profilbild klicken.
2
Settings öffnen.
3
Links unten Developer settings auswählen.
4
Personal access tokens öffnen und möglichst Fine-grained tokens nutzen.
5
Neuen Token erzeugen, Ablaufdatum setzen und nur minimale Leserechte vergeben.

Empfohlene Rechte

Für öffentliche Repository-Analysen reichen minimale Leserechte. Die App schreibt nichts auf GitHub und benötigt keinen Zugriff auf private Inhalte, sofern keine privaten Repositories analysiert werden sollen.

  • Repository access: Public repositories oder ausgewählte Repositories
  • Contents: read-only, falls auswählbar
  • Metadata: read-only
  • Keine Schreibrechte vergeben

Token in GitSuccess nutzen

Den erzeugten Token kopieren und im Analyzer im Feld Personal Access Token optional verwenden einfügen. Danach Analyse starten.

Authorization: Bearer github_pat_... Accept: application/vnd.github+json X-GitHub-Api-Version: 2022-11-28

Verwendete REST-Endpunkte

GitSuccess nutzt mehrere GitHub REST API Endpunkte zur Berechnung der Kennzahlen.

GET /repos/{owner}/{repo} GET /repos/{owner}/{repo}/stats/commit_activity GET /repos/{owner}/{repo}/readme GET /repos/{owner}/{repo}/contents/CONTRIBUTING.md GET /repos/{owner}/{repo}/releases?per_page=20 GET /repos/{owner}/{repo}/issues?state=all&per_page=100 GET /repos/{owner}/{repo}/contributors?per_page=100
