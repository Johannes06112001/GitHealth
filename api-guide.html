REST-API Guide

Diese Seite erklärt, wie Nutzer einen GitHub Token erstellen, warum er benötigt wird und welche GitHub REST-Endpunkte GitSuccess verwendet. Damit niemand mehr einen Token sucht, als wäre er in Mordor versteckt.

Kurzfassung: Für öffentliche Repositories reicht ein Personal Access Token mit Leserechten. Der Token wird nur im Browserfeld verwendet und nicht im Repository gespeichert.

1. GitHub Token erstellen

Schritt 1: GitHub Settings öffnen

GitHub öffnen, rechts oben auf das Profilbild klicken und Settings auswählen.

Schritt 2: Developer settings

Links unten Developer settings öffnen und danach Personal access tokens auswählen.

Schritt 3: Fine-grained Token

Fine-grained tokens wählen und einen neuen Token erstellen. Fine-grained ist besser, weil Rechte genauer begrenzt werden können.

Schritt 4: Rechte setzen

Für öffentliche Repositories genügt Zugriff auf öffentliche Repositories beziehungsweise minimaler Read-Zugriff. Schreibrechte sind für GitSuccess nicht erforderlich.

Schritt 5: Token kopieren

Nach dem Erstellen wird der Token nur einmal angezeigt. Direkt kopieren und im Analyzer in das Token-Feld einfügen.

2. Warum braucht GitSuccess einen Token?

GitHub erlaubt ohne Anmeldung nur eine begrenzte Anzahl API-Anfragen pro Stunde. Da GitSuccess mehrere Endpunkte abfragt, kann das Limit schnell erreicht werden. Mit Token wird das Limit deutlich erhöht und die Analyse läuft zuverlässiger.

Authorization: Bearer github_pat_...

Der Token wird nur clientseitig im Browser für API-Anfragen genutzt. Die Anwendung speichert ihn nicht dauerhaft und schreibt ihn nicht in Dateien.

3. Verwendete REST-Endpunkte

GitSuccess nutzt mehrere GitHub REST API Endpunkte, um Repository-Daten, Aktivität, Wartung und Dokumentation zu berechnen.

GET /repos/{owner}/{repo}

Basisdaten: Stars, Forks, Beschreibung, Sprache, Lizenz, Alter, offene Issues.

GET /repos/{owner}/{repo}/stats/commit_activity

Commit-Aktivität der letzten Wochen. Daraus wird die Aktivität der letzten 30 Tage abgeleitet.

GET /repos/{owner}/{repo}/contributors?per_page=100

Contributor-Anzahl als Community- und Resilienzsignal.

GET /repos/{owner}/{repo}/issues?state=all&per_page=100

Issue-Schließungsrate, durchschnittliche Schließzeit und Engagement.

GET /repos/{owner}/{repo}/releases?per_page=20

Release-Frequenz und Regelmäßigkeit.

GET /repos/{owner}/{repo}/readme

Prüfung, ob eine README vorhanden ist.

GET /repos/{owner}/{repo}/contents/CONTRIBUTING.md

Prüfung, ob ein Contribution-Leitfaden vorhanden ist.

4. Typische Fehler

Rate Limit exceeded

Ein Token fehlt oder das Limit wurde erreicht. Lösung: Token einfügen oder später erneut testen.

404 Repository nicht gefunden

Repository-Name prüfen. Private Repositories benötigen passende Leserechte.

Unvollständige Daten

Einige API-Endpunkte liefern bei kleinen oder neuen Repositories keine Daten. GitSuccess behandelt diese Werte als fehlend statt als automatisch schlecht.

5. Beispiel für direkte API-Abfrage

Wer testen will, ob der Token funktioniert, kann im Terminal eine direkte Anfrage ausführen:

curl -H "Authorization: Bearer DEIN_TOKEN" https://api.github.com/repos/facebook/react

Wenn JSON-Daten zurückkommen, funktioniert der Zugriff. Wenn GitHub meckert, hat entweder der Token falsche Rechte oder das Internet hat wieder beschlossen, Drama zu spielen.
